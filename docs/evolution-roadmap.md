# XCLI 演进路线图

本文记录 XCLI 后续演进的候选工作、依赖关系和决策状态，供跨会话、跨提交持续迭代。每个阶段的验证要求见 [迭代验收规范](evolution-acceptance.md)。已有操作以 [README](../README.md) 和 [发布与回退](operations/releases.md) 为准；实际部署状态、版本和配置应在操作前重新检查。

本文建立于 2026-11-04，审查基线为提交 `6a5f000`。除另有决策的项目外，以下阶段均为候选方案；顺序为讨论建议。用户已要求将后端业务服务重构为 Rust、Web 后端使用 Node.js / TypeScript、前端使用 Vue / TypeScript，并在重构完成后部署到香港；范围、迁移约束和进度见 [重构计划](rust-refactor.md)。新的明确指示优先于本文。

## 目标和边界

- 支持一个管理面板管理本机入口和多个独立节点，由管理员授权用户使用节点。
- 保留既有用户、订阅凭据、节点身份、流量、规则和客户端手动选择，除非本次任务明确要求改变；无法保留时先列出影响和迁移方案。
- 区分管理面板、节点数据转发、订阅生成、客户端规则和真实出口。每一层使用对应的证据判断状态。
- 保持私有部署的实用性；设备自助、开放 API 和商业化仅作为候选方向，不假设一定实现。
- 生产操作先核对目标、实际运行状态、备份和回退路径；不同服务器的部署和授权分别确认。不得把代码合并、构建成功或服务器探测成功当成客户端验收成功。
- 不把订阅链接、令牌、密码、密钥、用户 UUID、完整真实配置或其他凭据写入仓库、工单、验收记录或日志。使用脱敏信息、合成数据或受保护的本机证据。

## 候选阶段

状态统一使用：**待讨论 → 已确认 → 进行中 → 待验收 → 已完成**；取消的项目标记为 **已取消** 并记录原因。阶段可以拆分，但进入“已确认”前应记录范围和验收目标。上线授权按实际任务单独判断。

| 编号 | 阶段 | 主要结果 | 依赖 | 状态 |
| --- | --- | --- | --- | --- |
| E1 | 订阅状态与客户端配置诊断 | 按用户、格式显示发布状态、最近获取及配置摘要；明确客户端启用状态是否已知 | 明确采集和隐私边界 | 进行中：只读生成诊断 |
| E2 | 规则解释与发布历史 | 按用户和客户端解释规则来源、匹配顺序、目标和配置差异；支持历史版本回退 | 明确规则模拟能力和客户端差异 | 待讨论 |
| E3 | 异地备份与恢复演练 | 加密备份异地保存、完整性检查、隔离恢复演练和结果展示 | 确定存储目标、密钥保管和恢复范围 | 待讨论 |
| E4 | 独立节点升级与状态 | 节点原地升级、预检查、失败恢复，以及期望和已应用版本展示 | 节点身份、账本与版本兼容策略 | 待讨论 |
| E5 | 多节点计量与离线授权 | 定义周期、重报、清零和离线可用性，完善节点账本与面板同步 | 先确定配额精度、离线宽限和撤权取舍 | 待讨论 |
| E6 | 外部探测与选路 | 多地点检测节点与目标路径，展示样本和故障；自动选路单独决定 | 探测位置、凭据、频率和隐私 | 待讨论 |
| E7 | 设备、自助、管理员和 API | 按需引入设备凭据、用户自助、管理员角色及可撤销 API 凭据 | 产品使用规模与权限模型 | 待讨论 |
| E8 | 商业化 | 如有需要，再设计套餐、权益、支付和对账 | E3、E4、E5 的可靠性及服务条款评估 | 待讨论 |

### E1：订阅与配置诊断

分别识别 Clash 订阅、小火箭节点订阅和小火箭远程配置。建议显示模板版本、可安全展示的入口域名、生成摘要、最近成功获取时间、节点数量和策略组；错误显示原因。区分“服务端已发布”“服务端观察到请求”和“客户端已启用”，无法观察的状态显示未知。

长期稳定订阅入口可作为独立子项讨论。旧域名停用后，仍固定使用旧地址的客户端无法仅靠新服务器自动迁移；兼容转发需要旧入口可用，重定向及客户端是否保存新地址必须实机验证。不得在未经授权的服务器上建立兼容入口。

### E2：规则解释和发布历史

输入目标、用户和客户端类型，按实际生成的规则顺序展示匹配规则、来源与策略目标，并给出草稿与发布版本差异、影响用户和可回退的版本。系统规则、模板规则、历史底稿和兜底规则应可区分。客户端保留的选择、DNS 和运行模式若不可观测，标为未知；模拟结果不是实机流量证明。

### E3：异地备份和演练

候选范围包括备份上传、校验、保留期、失败通知和隔离恢复检查。备份加密密钥与备份分开保管；报告记录备份创建、异地保存和恢复演练各自结果。先明确是否包含节点账本、TLS、Nginx 和系统配置，以及新机器恢复时如何保留目标机器身份。

### E4：独立节点升级

先提供节点本机可执行的预检查、升级和回退，保留节点身份、注册密钥、流量账本和证书。面板应区分节点连接状态、配置待应用状态和已确认版本。远程触发升级作为独立决策，不默认授予面板任意远程命令执行能力。

### E5：多节点流量与离线策略

设计周期或代次标识、累计计数与确认机制，处理重试、清零、计数回退、节点离线后恢复和面板备份恢复。配额超额容忍度、离线授权时长和撤权生效时间相互制约，必须先确定产品语义；不得将延长租约等同于解决分布式配额。

### E6 至 E8

E6 先建设有来源和采样时间的外部探测，自动切换需另行定义触发阈值、恢复和现有连接行为。E7 的设备凭据不能依赖 IP 数或订阅请求数推断设备身份。E8 的支付确认、权益、计量与对账应分开设计；在需要此能力前不引入订单和支付系统。

## 待确认决策

| 决策 | 待讨论问题 |
| --- | --- |
| 产品定位 | 私人及亲友使用，还是面向更多用户运营；决定 E7、E8 的范围 |
| 订阅入口 | 是否使用独立稳定域名；旧入口维护多久；哪些部署允许调整 |
| 请求记录 | 记录哪些客户端类型、时间和网络信息；保留多久；如何关闭 |
| 恢复目标 | 异地存储位置、密钥保管方式、恢复点和恢复时间目标 |
| 节点离线 | 离线期间是否继续提供服务、允许多久；停用和配额变更最迟何时生效 |
| 计费周期 | 清零语义、计量误差容忍、异常账本处理方式 |
| 探测 | 哪些地区和运营商、哪些目标、探测频率和凭据管理 |
