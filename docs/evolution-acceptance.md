# XCLI 迭代验收规范

本文为 [演进路线图](evolution-roadmap.md) 中的候选阶段提供可重复的验收场景。阶段尚未确认前，这些条目是**候选验收标准**，不代表功能已有实现或已授权上线。实施前应确定适用范围、测试环境、预期结果和可接受误差；不适用项说明理由，未执行项保留为待验证。

## 通用完成条件

每项工作应记录需求与非目标、影响范围、兼容性、迁移与回退、风险和验证结果。验收分为四层，不得用前一层代替后一层：

| 验证层 | 需要证明的内容 |
| --- | --- |
| 自动化测试 | 核心行为、边界和失败处理在隔离环境下符合预期；测试结果和跳过项有记录 |
| 集成与故障测试 | 组件按真实接口交互，关键异常、重启和恢复路径可复现 |
| 目标环境检查 | 指定部署版本、配置、进程和相关服务状态符合本次变更预期 |
| 客户端验收 | 需要客户端的功能在指定客户端、版本和网络上实测；由用户操作时记录其反馈及未覆盖范围 |

适用时，以下条件全部满足才将工作标记为完成：

- 变更有明确范围；既有用户、节点、凭据、模板、累计流量及客户端选择的兼容性已检查。需要主动改变的项目单独列出。
- 对行为有意义的测试通过；失败或跳过项列出原因及影响。不为了完成清单而执行不相关测试。
- 针对旧版本数据、新安装、升级及回退建立适合本次改动的验证；涉及数据库结构时明确前后版本兼容及不可逆操作。
- 变更影响的文档已更新；自动生成内容或用户界面不存在把计划描述成已实现的陈述。
- 涉及生产时，发布前确认实际目标、当前版本、配置、健康状态、一致性备份和适用回退方案；按现有 [发布与回退流程](operations/releases.md) 操作。代码回退不等于数据库恢复。
- 生产验证记录实际进程及必要的真实请求或连接；涉及客户端时记录客户端结果。重启或切换会影响连接时，事先明确范围与影响，并按任务授权操作。
- 安全记录不包含密码、令牌、订阅链接、UUID、私钥、完整真实配置或用户访问内容。测试账户和探测凭据使用最小权限，并在任务结束后按约定清理或保留。

## E1：订阅状态与客户端配置诊断

- 为测试用户生成 Clash 订阅、小火箭节点订阅和远程配置；分别核对用户归属、版本、摘要、节点数及策略组。使用不同模板和未配置模板的用户验证隔离。
- 客户端请求成功、失败及未请求时状态不同；页面区分已发布、已请求和启用状态未知。请求时间与服务端时钟和采样时间有明确含义。
- 在不同客户端或不同入口发起请求，核对可观测的格式和域名；不根据 User-Agent 单独断言设备身份或配置已启用。
- 若实现历史或诊断记录，验证保留期、关闭开关、访问控制和清理；响应与日志不暴露订阅令牌。
- 如果改动旧入口兼容，分别测试需要迁移与不应迁移的路径、参数和其他站点；在真实客户端核对节点订阅和远程配置各自的更新行为。重定向成功不代表客户端永久保存了新地址；旧入口下线场景单独验证。
- 使用 Clash 和小火箭真实设备验证时，分别记录服务端生成、客户端刷新、启用及实际节点选择；未接触到真实设备时标记待验证。

## E2：规则解释与发布历史

- 使用合成配置覆盖精确域名、后缀、关键词、IP、兜底和规则覆盖；示例至少包含 Google、Gemini、YouTube、私网及系统优先规则，核对先后匹配和规则来源。
- 分别比较 Clash 与小火箭输出。客户端不支持的类型须明确标识或拒绝，不能静默改为另一行为。
- 展示规则目标与服务端可知的默认策略链；客户端持久化选择、DNS、运行模式和实际出口未知时明确标注。
- 发布前预览新增、删除、排序及目标变化，并正确列出受影响用户；并发修改或旧版本提交被拒绝。
- 回滚历史版本前可预览差异，发布后按新版本管理；对未选择该模板的用户，生成结果保持原行为。
- 对规则模拟与真实客户端的差异建立样例；服务端模拟和文本校验通过不等于客户端实际分流通过。

## E3：异地备份与恢复演练

- 验证加密备份上传、下载、完整性检查、保留和按约定清理；传输失败、中断、空间不足及认证错误产生可观察结果，不删除最后可用备份。
- 错误密钥、损坏文件和不兼容版本明确失败；密钥不出现在备份目标、日志或页面响应中。
- 在隔离环境演练恢复，验证数据库完整性、用户身份、订阅凭据、模板、节点注册及各项已承诺恢复的数据；验证哪些机器专属配置按设计保留或重建。
- 在线恢复与离线灾难恢复分别测试。恢复过程不得让两个运行中的实例同时使用冲突身份；不得用旧快照覆盖未确认的当前数据。
- 展示备份创建、异地保存和恢复演练的独立时间与结果；无成功演练时显示未知或未演练。
- 约定恢复点、恢复时间和演练频率后再测量；没有约定或样本不足时不声称达到某个目标。

## E4：独立节点升级与状态

- 在受支持的系统和架构上验证预检查、安装候选版本、健康检查与升级成功；版本不兼容、空间不足、锁冲突、包校验失败时保留原服务。
- 升级前后核对节点身份、注册密钥、TLS、授权用户、本地账本、累计流量及配置；验证三种已启用入口和节点到面板的同步。
- 模拟升级中断、候选进程启动失败和升级后健康检查失败，验证恢复或明确提示人工恢复；检查面板状态与节点真实状态一致。
- 展示节点当前版本、期望版本、已应用配置版本、最后同步时间及过期状态；不能因为心跳成功就显示用户网络入口已验证。
- 对新旧面板及节点的支持组合建立兼容矩阵。面板远程升级如果被纳入范围，另行验证授权、任务幂等和权限边界。

## E5：多节点计量与离线授权

正式实现前先固定周期定义、允许的计量误差、节点离线行为、撤权延迟和异常处理；没有这些决策时不能声称配额精确或离线行为符合业务目标。

- 模拟重复、乱序、延迟和丢失响应，验证重报不会重复计数，确认点持久化后可继续同步。
- 覆盖节点断网、进程重启、系统异常退出、计数器回退及账本恢复；核对已上报与待上报数据，并明确可能丢失的采样窗口。
- 在节点离线、在线和多节点并发场景执行周期切换或清零，验证旧周期报告不会写入新周期，也不会丢失已确认用量。
- 恢复面板旧备份并重新连接节点，验证计数基线、用户删除与授权变化不会造成重复计数或复活已撤销权限。
- 达到配额、用户到期或撤权时，测量各节点新连接和已有连接的实际行为；记录同步延迟与允许超额，不使用“实时”“精确”替代测量。
- 面板不可用超过授权租约或宽限期时，实测节点、客户端和恢复后状态；同时验证新旧协议兼容及管理员可见的过期提示。

## E6：外部探测与选路

- 在至少一个受控外部探测点验证入口、DNS 和目标请求，报告来源、时间、样本量、成功率与延迟；服务端自检和外部结果分别呈现。
- 故障、超时、未知和数据过期分别处理；短暂波动、连续失败和恢复触发符合约定的告警阈值。
- 探测账户可撤销，探测目标和频率可配置；不采集真实用户流量或访问网站记录。
- 若启用自动切换，分别测试失败触发、恢复、抖动、冷却、已有连接以及客户端手动选择；明确测速目标不能代表其他目标的可用性。

## E7 和 E8：按确认范围补充

E7 若涉及设备凭据，验证单设备撤销不会影响其他设备，同时覆盖凭据轮换和旧用户迁移；管理员角色及 API 需验证越权、令牌撤销和审计。E8 若涉及支付，需在隔离环境验证重复回调、乱序、退款、权益生效和对账；测试支付成功不等于生产支付或商业运营获准。

## Rust 重构：受控重启的用量与撤权

2026-11-05 用户确认：允许最后一次采样到 Xray 退出之间产生的流量未计入。以下检查仍为上线条件：

- 在隔离环境以持续流量验证：核对核心代次，采集非重置累计计数并成功提交数据库，之后才执行受控重启；记录采样与停止之间可能漏计，不能声称精确结算。
- 分别覆盖撤权、导入配置应用、升级和恢复等实际重启入口；采样、数据库提交、代次核对或重启失败时，不能显示操作已完成。需要记录是否仍存在可用的旧连接以及告警与处理方式。
- 新旧面板和导入进程不得并发写入；回退使用切换期间持续更新的状态，不覆盖已提交用量。异常崩溃、宿主机断电和独立节点尚未上报的用量单独验证，不属于上述受控重启窗口。

## Rust 重构：证书和运行时依赖

- 对面板、节点、导入、住宅池、监测、通知，以及开机和续期触发的自有程序逐一列出实际运行版本和调用链；旧 C++、Python 常驻服务、定时任务或自有钩子不得被遗漏。Certbot、Xray、Nginx、OpenSSL 等第三方组件单独列出，不因其内部实现语言推断为 XCLI 自有服务。
- 使用合成证书覆盖正确域名、错误域名、私钥不匹配、即将到期、损坏输入以及命令超时；日志、进程参数和报告不包含私钥内容。
- 在隔离环境验证 Certbot 的证书链接、文件所有权及权限、多个不同域名的钩子过滤，确认无关入口不会被重载或覆盖。
- 发布前分别在文件暂存、切换和服务重载阶段注入失败或进程中断，证明旧证书对仍可使用或能明确恢复；不得只依据两个文件各自原子替换就声称证书对一致。
- 使用真实测试客户端对 Nginx 及 Xray 新建连接，核对续期前后证书、公私钥匹配、域名和现有连接行为；运行中的核心如何重新加载证书须实测。
- 记录实际部署的钩子归属、更新路径及回退方式。其他站点或证书的钩子只有在明确作用域并完成各自验证后才能迁移或移除。

## 单次迭代验收记录

每个阶段或子任务应在路线图迭代记录中填写摘要，复杂任务可另建专项记录。记录至少包含：

- 范围、非目标、已确认的决策及对应阶段。
- 基线与最终提交、目标环境和实际运行版本；代码合并、推送及部署分别记录。
- 自动化、集成、目标环境与客户端的命令或方法、结果、跳过项及证据位置；仅记录脱敏信息。
- 对用户、节点、订阅、流量、客户端手动选择的影响和检查结果。
- 故障注入结果、回退或恢复方法、未完成项、已知限制及下一步。

验收结果使用“通过 / 失败 / 待验证 / 不适用”。有失败或待验证项时列出影响，不将整个阶段标记为已完成；若只要求交付部分范围，应明确该部分完成及其余工作状态。
