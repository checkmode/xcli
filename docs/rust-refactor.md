# Rust 与 TypeScript 重构及香港迁移

本计划记录用户确认的技术方向、旧版兼容范围、迁移阶段和可审计的验收证据。建立基线为 `6a5f000`，本地已有未提交的订阅诊断及路线图工作，必须保留并迁移其行为。新版与旧版并行开发；除非本文件记录实际完成和验证，阶段均不能视为已实现。

## 已确认方向

- XCLI 自有后端业务服务使用 Rust；Web 接入后端使用 Node.js / TypeScript，网页前端使用 Vue / TypeScript。
- 重构并部署到香港。2026-11-05 用户确认香港当前无人使用，可以中断服务并丢弃旧数据；新面板从空用户数据库开始，原香港订阅和节点身份不迁移。
- 官方 Xray-core 和 Nginx 属于第三方运行组件，不在 XCLI 自有业务代码改写范围；协议数据仍由 Xray-core 转发。安装脚本等非运行服务应逐项清理或迁移，不能以保留一个 Python 常驻工作进程宣称“全部后端已迁移”。
- 技术栈变化本身不证明性能或可靠性提升；基于同硬件、同数据、同负载比较，记录吞吐、延迟、资源、失败率和测试方法。

## 服务边界

| 组件 | 目标职责 | 约束 |
| --- | --- | --- |
| Vue / TypeScript | 管理页面、表单、客户端向导 | 保持现有功能、响应式布局、中文文案和敏感字段不回显 |
| Node.js / TypeScript Web 后端 | 同源静态资源、Web 请求接入、向固定 Rust 服务转发 | 监听回环；不接收任意转发目标；透传认证、CSRF、订阅响应和流式内容；不记录含凭据的路径 |
| Rust 面板服务 | 登录、用户、订阅、规则、节点授权、流量、备份、通知和业务 API | 唯一业务数据写入者；兼容现有 API、安全语义和数据库迁移 |
| Rust 独立节点服务 | 面板同步、授权租约、Xray 管理、本地账本与幂等重报 | 继承已有节点身份和账本；过期授权与核心故障保持安全边界 |
| Rust 导入、住宅池和探测服务 | 代理探测和配置事务、动态住宅会话及转发、入口健康检查 | 按现有权限隔离，保持失败回退和凭据保护；不得把 root 权限整体授予 Web 进程 |
| 发布和安装工具 | 新旧安装、预检查、升级、备份、回退和恢复 | 支持现有部署和全新机器；不得依赖手工复制未提交代码 |

Web 后端不是第二个用户数据库，也不是绕过 Rust 鉴权的入口。客户端订阅和节点同步必须能保留现有 URL、状态码、响应头、内容格式、TLS 和认证语义；Xray/Nginx 的使用及路径是否变化以可验证的迁移方案为准。

## 实施顺序和完成条件

1. 固化旧版接口和合成测试数据，建立 Rust / TypeScript 工程、自动化检查和可重复的旧新对照测试。先处理独立节点账本：维持 SQLite 格式、事务、累计计数与确认语义，使用旧实现产生的数据交叉验证。此阶段不接管真实节点。
2. 迁移 Rust 节点服务与面板业务，覆盖租约、认证、规则、订阅和计量；同一时刻只允许一个实现写生产数据库和控制同一 Xray 核心。逐项核对接口与故障行为。
3. 迁移导入、住宅池、探测、告警、备份及维护服务，建立跨进程权限边界和可回退配置事务。
4. 构建 Node.js 接入层和 Vue 界面；通过旧版管理流程、移动端布局和真实客户端检查。
5. 完成全新安装、双栈入口和服务验证，并进行同条件性能对照。其他需要保留数据的服务器仍需单独完成迁移与回退方案。
6. 香港已按用户允许中断和丢弃旧数据的范围安装实验版；继续完成真实客户端、住宅供应商、独立节点和正式发布验收。

正式发布前仍需完成真实客户端、独立节点、通知和完整管理流程验收。香港的新部署无需迁移旧身份与用量；美国已完成一次保留用户数据的实验性迁移，其他有用户的服务器仍需单独核对。香港和美国的面板、监测及固定代理导入服务现由 Rust 和 Node 运行，Xray、Nginx 及系统 Certbot 属于外部组件。

正常使用中的升级、撤权等受控重启沿用旧版方式：先采样并提交用量，再停止核心；用户接受最后一次采样到退出之间可能漏计。此次香港从空数据库重装是用户允许丢弃旧数据的特例，不要求交接旧流量；此决定不自动适用于其他有用户的服务器。

隔离测试验证了不重启 Xray 时，旧面板 → Rust 面板 → 旧面板可以共享同一份当前数据库和核心累计计数，切换间隙的流量在后续采样中补入；这一结果仅覆盖合成数据和一条 VLESS/WebSocket 连接。Xray 26.10.21 的[入站关闭实现](https://github.com/XTLS/Xray-core/blob/v26.10.21/app/proxyman/inbound/worker.go)会关闭监听器和代理，但实测删除入口或[动态移除用户](https://github.com/XTLS/Xray-core/blob/v26.10.21/proxy/vless/inbound/inbound.go)后，已有 TCP 会话仍可能继续；Hysteria 2 的既有 QUIC 连接还能创建新的数据流。在线 IP 统计也会[忽略回环地址](https://github.com/XTLS/Xray-core/blob/v26.10.21/app/stats/online_map.go)，不能作为所有会话结束的证明。受控重启仍需覆盖实际连接中断、用量采样、代次变化、失败告警和回退；导入、升级、恢复等调用路径尚未全部接入和验证。

## 香港部署边界

2026-11-04 只读检查显示香港运行旧面板、Xray、导入、监测、动态住宅池和 Nginx，TCP 443 已使用。此快照会变化，发布前必须重新核对。2026-11-05 用户确认香港当前无人使用，可以停服，旧数据也可以丢失；香港按全新面板部署即可，不再要求迁移用户或实现无缝交接。美国等其他服务器和域名不在此次部署范围内。

替换前检查到旧部署包含两个 Hysteria 证书入口和四个旧 XCLI 续期钩子。按用户确认的香港全新安装范围，旧服务已停用，旧钩子已归档；新面板只服务 `hk.xdistribute.tech`，使用其现有 Certbot 证书和新 Rust 钩子。美国服务器及其 DNS 记录未调整。

对于现用 Xray 26.10.21，其[证书热加载代码](https://github.com/XTLS/Xray-core/blob/v26.10.21/transport/internet/tls/config.go)分别读取证书和私钥；默认检查周期为一小时，文件读取失败会结束该加载循环，无效证书对则不会替换当前可用证书。因而续期测试必须涵盖两个文件之间的中断和读取失败，不能只检查磁盘上的文件或假定更新立即生效；上述行为仍须与目标配置和实际握手结合验证。

当前实验性 HTTP 服务只监听回环地址，Node 网关透传 Nginx 设置的 `X-Forwarded-For`，不能直接暴露公网。认证、用户、订阅、规则、在线恢复、节点同步和住宅控制等接口已接入；香港实验部署已完成基本端到端测试，大并发及其余业务尚待验收。

实验面板可显式使用 `--experimental-strict-settings true`，在打开数据库及启动采样前检查旧版配置结构。此检查仍在对照中，默认关闭，也不会验证证书文件、端口监听、出口连通性或 Xray 运行状态；完整安装与部署流程必须接入并验证，不可将选项本身当作上线许可。

Rust 服务定义与实验安装器位于 `rewrite/deploy/`。其中静态导入示例默认只预览；实验性新安装器根据服务账户和路径生成 `mode: apply` 配置。香港使用 `reinstall-legacy.py` 替换旧服务，并从空数据库启动。

`install.sh` 下载指定提交并调用 `rewrite/install-experimental.sh`；从 Git 检出运行时默认选择当前提交，未提交的工作不会进入安装包。新版安装器面向干净主机，旧版单机面板可使用 `upgrade.sh` 保留数据迁移到实验版；旧版安装须显式传入 `--legacy`。香港此次使用工作区未提交源码构建的实验包，并非 Git 提交或正式发布包；发布包不自带 Xray 或 Node 运行时。
